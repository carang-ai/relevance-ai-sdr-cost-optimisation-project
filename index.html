The Challenge

A platform crisis in slow motion

Relevance AI sits on a single allocation shared across every team at Employment Hero using the platform. When that allocation runs dry, everything on it stops — not just the team that exhausted it. Our AI SDR workforces were among the biggest draws, and by mid-year were on track to exhaust it by around November.

The situation

Across eight AI SDR workforces, each prospect was being processed at 12–16 actions and 4–8 search runs — a design inherited from early proof-of-concept builds where throughput wasn't a constraint. As volume grew, that cost-per-lead profile didn't shrink. It compounded. AU/NZ Outbound alone roughly doubled in run volume since June. At the old architecture, that would have doubled our footprint too.

Root causes

  • Architectural bloat — multi-step tool chains billing separately for every sub-call
  • Redundant cloned agents spun up per region with no shared optimization baseline
  • Silent error billing — one intel tool billed every run despite a ~100% failure rate across ~780 runs
  • "Set-and-forget" governance — workforces deployed and never audited for cost efficiency
  • No eval framework — cheaper rewrites couldn't be validated, so no one shipped them
Important context: Despite a recent contract top-up, ongoing optimization remains mandatory. Run volumes are still growing — this work builds structural efficiency, not one-time relief.

Fixes We Put In Place

Seven changes across all eight workforces

The same patterns apply to any team running Relevance AI — including the two platform-specific bugs that would have been impossible to find without knowing how the platform handles code internally.

01
Tool Stacking & Consolidation Highest impact

Multiple separately-billed lookups were collapsed into single consolidated tools that run all steps internally. You're billed for the tool call, not what happens inside it. On our heaviest research agent, this took actions per agent run down ~70% and dropped its error rate from 2.5% to 0%.

Before: website scrape + 3 searches + LinkedIn lookup + conditional search + synthesis = 8 billed actions. After: one consolidated research tool = 1 billed action.
02
Silent Error Elimination

We audited tool failure rates — not whether tools "usually work", but whether they bill on failure. You're charged for the attempt regardless of outcome. A tool that fails consistently is a billing tax with zero output value.

One lookup tool billed on all ~780 of its runs at a ~100% failure rate. Removed entirely — we had been paying for work that never happened once.
03
Prompt Tightening & Toolbox Trimming

Shorter instruction sets and fewer available tools reduce unnecessary reasoning steps. Each unreachable tool is still a context cost. Each redundant instruction is noise the model processes and discards before doing useful work.

AU/NZ orchestrator instructions: 11,389 → 9,862 characters (zero logic change). Research agent available tools: 15 → 11.
04
Rebuild Once, Stop Maintaining Clones

A fix applied to one regional clone never reaches the others — inefficiencies and bugs duplicate silently across forks. Consolidating to a shared base means every improvement propagates everywhere automatically.

Canada had drifted into its own lineage with diverged bugs. Rebuilt to mirror the already-optimized AU/NZ base — one fix now flows everywhere.
05
Gate Every Change Behind a Score

"Cheaper" is easy to prove. "Not worse" requires a real measurement. Without an eval framework, optimized versions don't ship because the quality risk is invisible. With one, it's quantified — and beatable.

No rebuilt workforce went live until it scored equal to or better than its predecessor. The process also surfaced 4 silent production bugs that had never been caught.
06
Calendar Link: Platform Source Text Fix

Relevance AI scans the stored source text of code before executing it — not just the computed value. A calendar link variable written as {{ calendar_link }} triggered a template substitution that blanked the tag at runtime, even though the code was logically correct. The fix was building the brace characters with chr(123)*2 rather than typing them directly. This was one of four independent failure modes all producing the same symptom simultaneously, which made it look like fixes weren't working even when real progress was happening.

Before: {{ calendar_link }} typed directly → blanked at runtime. After: chr(123)*2 + "calendar_link" + chr(125)*2 → works correctly.
07
Case Study Tools: Region Logic & URL Regex

The NZ and UK case-study tools had two bugs stacked: no UK branch in the region-matching logic meant those leads fell through to an unrestricted search, and a broken URL regex silently dropped all NZ and UK locale-prefixed links even when matching worked. Both had to be present for the full failure — fixing one alone still produced wrong output. Adding the missing branch and broadening the regex unlocked 22 NZ and 41 UK case studies that had been sitting unused in Asana the whole time.

Before: UK leads got zero case-study matches; NZ/UK links silently dropped. After: 22 NZ + 41 UK case studies now reachable.

Summary

Half the cost. More reliable. Quality unchanged.

~37% reduction in our total platform footprint — runway handed back to every team on the shared Relevance AI allocation.

What we achieved
Half the cost per lead. Zero change in output.

Eight AI SDR workforces rebuilt from audit to deployment. Actions per run down ~45%, credits down ~42%, ~10,600 actions saved every week at current volume. At the old architecture, these workforces would now be consuming ~124k actions/month. They're at ~78k.

Error rates on the two workforces that had measurable failures before now sit at 0%. Every change shipped only after passing a purpose-built eval framework — output quality was the one constraint we wouldn't move.

What's next
Structural efficiency, not a one-time fix.

A top-up was secured from Relevance, so the immediate November cliff is gone — but a top-up only moves the wall. Volume is still growing fast. The work here builds structural efficiency: cost per run is now decoupled from volume, so as AU/NZ Outbound doubles again, the footprint doesn't.

Consumption is now monitored per workforce continuously, not reviewed at renewal. Silent tool failures are actively watched for. The remaining smaller workforces are next in the pipeline.

An open offer
The playbook is yours to borrow.

Since ~37% of our footprint is runway handed back to everyone on the same allocation, the patterns here are worth applying across the org. Tool stacking, prompt tightening, and checking whether tools are silently billing for failed runs — that last one takes minutes to check and was costing us ~780 billed actions on a single tool alone.

Happy to walk any team through what we did, share the eval framework, or review a specific workforce together.
