The Challenge

A platform crisis in slow motion

Our AI SDR workforces were consuming the shared Relevance AI allowance at a rate heading toward a full platform shutdown — affecting every team, not just ours.

The situation

Across eight AI SDR workforces, each prospect was being processed at 12–16 actions and 4–8 search runs — a design inherited from early proof-of-concept builds where throughput wasn't yet a constraint. As volume grew, that cost-per-lead profile didn't shrink. It compounded.

Root causes

  • Architectural bloat — multi-step tool chains billing separately for every sub-call
  • Redundant cloned agents spun up per region with no shared optimization baseline
  • Silent error billing — one intel tool billed every run despite a ~100% failure rate across ~780 runs
  • "Set-and-forget" governance — workforces deployed and never audited for cost efficiency
  • No eval framework — cheaper rewrites couldn't be validated, so no one shipped them
Important context: Despite a recent contract top-up, ongoing optimization remains mandatory. Run volumes are still growing — this work builds structural efficiency, not one-time relief.

Bug Deep-Dives

Two production bugs that were invisible by design

Neither was a logic error you could reason your way to from code behavior alone. Both required understanding a layer underneath the code — the platform's runtime assumptions — before the fix became visible.

Platform internals bug · Stacked (4 layers)
Calendar Link: Same Code, Wrong Behavior
The crux

The code looked completely correct. You could stare at it all day — it's valid, sensible Python. The bug wasn't in the logic; it was in a layer underneath the logic that rewrites source text before executing it. Almost all debugging assumes that if two pieces of code compute the same value, they behave the same. Here, that assumption was false.

The fix — only visible by diffing character-by-character
Broken {{ calendar_link }}
Fixed chr(123)*2 + "calendar_link" + chr(125)*2
Both produce the identical runtime string. The difference is that Relevance scans the stored source text of the code — not just the value it computes — and {{ typed directly triggers a template substitution pass that blanks the tag. chr(123)*2 bypasses the scanner entirely. You'd only find this by knowing the platform behaves this way, which isn't something you'd normally think to check.
Why it looked like "nothing is working" — 4 stacked bugs, 1 symptom
  • L1Relevance's state layer sometimes blanking the tag when read across step boundaries
  • L2Source-code text-scanning issue — the one above
  • L3Orchestrator agent occasionally deciding "undefined" was the correct value and overriding a correct result
  • L4Orchestrator sometimes downplaying a real failure in its summary ("known issue, doesn't affect delivery")
Why the environment was a red herring

An equivalent fix worked fine on a different workforce writing to the same Outreach org. That made us test OAuth accounts, HTML structure, and tool wiring — all plausible suspects, all ruled out against production. The environment really was identical. The difference was purely in how the brace characters were written in source.

Logic bug · Stacked (2 layers)
Case Study Tools: Two Bugs, One Silent Result
The symptom

NZ and UK leads were receiving poor or irrelevant case study matches. The tools appeared to run without errors — output was produced — so there was no obvious signal that anything was wrong. The full pool of available case studies was being silently ignored.

Bug layer 1 — Missing region branch

The region-matching logic in the Asana lookup tool had no branch for UK at all. It only recognized AU and NZ. UK leads fell through to an unrestricted Google search that could surface any region's case study, with no quality or relevance control.

Bug layer 2 — Broken URL regex

The URL-extraction regex only recognized the unprefixed AU-style link format. It silently dropped almost every NZ (/nz/) and UK (/uk/) case study — even on runs where the region matching itself worked correctly. Both bugs had to be present for the failure to fully manifest; fixing one alone would still produce bad output.

The fix

Added the missing UK branch to the region logic. Broadened the regex to accept locale-prefixed URL formats. Both changes together unlocked the full existing pool of case studies that had been sitting unused in Asana throughout.

Optimization Blueprint

Replicable patterns for any Relevance AI team

Five patterns did almost all of the work. Any team running Relevance AI workforces can apply these directly.

01
Tool Stacking & Consolidation Highest impact

Combine multiple small, separately-billed lookups into a single consolidated tool that runs all steps internally and returns one answer. You're billed for the tool call, not the internal steps — this is the biggest single lever.

Before: website scrape + 3 searches + LinkedIn lookup + conditional search + synthesis = 8 billed actions.
After: one consolidated research tool = 1 billed action.
02
Silent Error Elimination

Audit your tool failure rates — not whether tools "usually work", but whether they bill on failure. You're charged for the attempt regardless of outcome. A tool that fails 50%+ of runs is a billing tax with zero output value.

One lookup tool failed on roughly 46–60% of runs every measured month. Removed entirely rather than continue paying for a coin flip.
03
Prompt Tightening & Toolbox Trimming

Shorter instruction sets and fewer available tools reduce unnecessary reasoning. Each unreachable tool is a context token cost with no upside. Each redundant instruction is noise the model has to process and discard.

AU/NZ orchestrator instructions: 11,389 → 9,862 characters (zero logic change). Research agent available tools: 15 → 11.
04
Rebuild Once, Stop Maintaining Clones

A fix applied to one regional clone never reaches the others. Inefficiencies get duplicated, bugs persist in forks, and every optimization requires N times the effort. A shared maintained base beats N regional divergences.

Canada had drifted into its own lineage. Rebuilt to mirror the already-optimized AU/NZ base — one fix now flows everywhere.
05
Gate Every Change Behind a Score

"Cheaper" is easy to prove. "Not worse" requires a real measurement. Without an eval framework, no one ships optimized versions because the risk is invisible. With one, the risk is quantified and defeatable.

No rebuilt workforce went live until it scored equal to or better than its predecessor. The eval process also caught 4 pre-existing silent production bugs.
