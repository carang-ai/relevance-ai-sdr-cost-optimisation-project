01 / The Challenge

A platform crisis in slow motion

Our AI SDR workforces were consuming the shared Relevance AI allowance at a rate heading toward a full platform shutdown — affecting every team, not just ours.

The situation

Across eight AI SDR workforces, each prospect was being processed at 12–16 actions and 4–8 search runs — a design inherited from early proof-of-concept builds where throughput wasn't yet a constraint. As volume grew, that cost-per-lead profile didn't shrink. It compounded.

Root causes

  • Architectural bloat — multi-step tool chains billing separately for every sub-call
  • Redundant cloned agents spun up per region with no shared optimization baseline
  • Silent error billing — one intel tool billed every run despite a ~100% failure rate across ~780 runs
  • "Set-and-forget" governance — workforces deployed and never audited for cost efficiency
  • No eval framework — cheaper rewrites couldn't be validated, so no one shipped them
Important context: Despite a recent contract top-up, ongoing optimization remains mandatory. Run volumes are still growing — this work builds structural efficiency, not one-time relief.

04 / Optimization Blueprint

Replicable patterns for any Relevance AI team

Five patterns did almost all of the work. Any team running Relevance AI workforces can apply these directly.

01
Tool Stacking & Consolidation Highest impact

Combine multiple small, separately-billed lookups into a single consolidated tool that runs all steps internally and returns one answer. You're billed for the tool call, not the internal steps — this is the biggest single lever.

Before: website scrape + 3 searches + LinkedIn lookup + conditional search + synthesis = 8 billed actions.
After: one consolidated research tool = 1 billed action.
02
Silent Error Elimination

Audit your tool failure rates — not whether tools "usually work", but whether they bill on failure. You're charged for the attempt regardless of outcome. A tool that fails 50%+ of runs is a billing tax with zero output value.

One lookup tool failed on roughly 46–60% of runs every measured month. Removed entirely rather than continue paying for a coin flip.
03
Prompt Tightening & Toolbox Trimming

Shorter instruction sets and fewer available tools reduce unnecessary reasoning. Each unreachable tool is a context token cost with no upside. Each redundant instruction is noise the model has to process and discard.

AU/NZ orchestrator instructions: 11,389 → 9,862 characters (zero logic change). Research agent available tools: 15 → 11.
04
Rebuild Once, Stop Maintaining Clones

A fix applied to one regional clone never reaches the others. Inefficiencies get duplicated, bugs persist in forks, and every optimization requires N times the effort. A shared maintained base beats N regional divergences.

Canada had drifted into its own lineage. Rebuilt to mirror the already-optimized AU/NZ base — one fix now flows everywhere.
05
Gate Every Change Behind a Score

"Cheaper" is easy to prove. "Not worse" requires a real measurement. Without an eval framework, no one ships optimized versions because the risk is invisible. With one, the risk is quantified and defeatable.

No rebuilt workforce went live until it scored equal to or better than its predecessor. The eval process also caught 4 pre-existing silent production bugs.
